# Ensure that Dataproc Cluster is encrypted using Customer-Managed Encryption Key

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Encryption of data-at-rest |

## Description

This control checks that Dataproc clusters encrypt their persistent disks with a customer-managed key. A `google_dataproc_cluster` must set `cluster_config.encryption_config.kms_key_name`, and a `google_dataproc_workflow_template` with a managed cluster must set `placement.managed_cluster.config.encryption_config.gce_pd_kms_key_name`. Clusters that use `virtual_cluster_config` (Dataproc on GKE) are excluded. Dataproc Serverless batches, session templates, and Dataproc Metastore are outside the scope of this control. A cluster that omits `cluster_config` is reported as unknown during a plan.

By default, Dataproc cluster disks are encrypted with Google-managed keys. Using a customer-managed key in Cloud KMS lets you control rotation, access, and revocation of the key that protects cluster data.

This rule is covered by the [8-1-dataproc-cmek](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/dataproc/8-1-dataproc-cmek.policy.hcl) policy.
