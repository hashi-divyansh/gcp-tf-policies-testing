# Ensure 'external scripts enabled' Database Flag for Cloud SQL SQL Server Instance Is Set to 'off'

| Provider | Category | CIS Control (GCP v5.0.0) |
| -------- | -------- | ------------------------ |
| Google Cloud Platform | Database security | 6.3.1 |

## Description

This control checks that Cloud SQL for SQL Server instances (`google_sql_database_instance` with a `SQLSERVER` `database_version`) set the `external scripts enabled` database flag to `off`, if it is set. Values are compared case-insensitively. If the flag is not set, the instance passes because the engine default is compliant. Read replicas are evaluated too, because database flags are not inherited from the primary. Database Migration Service connection profiles are not checked because their Cloud SQL destination supports only MySQL and PostgreSQL versions.

`external scripts enabled` allows R and Python scripts to run from T-SQL through external runtimes. Those scripts run outside the database engine's security boundary, so the feature should stay disabled unless it is required.

This rule is covered by the [cloudsql-sqlserver-external-scripts-disabled](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/sql/cloudsql-sqlserver-external-scripts-disabled.policy.hcl) policy.
