# Ensure Oslogin Is Enabled for a Project

| Provider | Category | CIS Control (GCP v5.0.0) |
| -------- | -------- | ------------------------ |
| Google Cloud Platform | Compute security | 4.4 |

## Description

This control checks that OS Login is enabled for Compute Engine. At the project level, a `google_compute_project_metadata` resource or a `google_compute_project_metadata_item` for `enable-oslogin` must set the value to a true value (`TRUE`, `true`, `True`, `T`, `t`, or `1`); an omitted or false value fails. At the instance level, `google_compute_instance`, `google_compute_instance_from_template`, `google_compute_instance_template`, and `google_compute_region_instance_template` may omit `enable-oslogin` to inherit the project setting, but if they set it, the value must be true.

A newly created `google_project` must have matching OS Login metadata in the same plan. The metadata resource's `project` must match the project's `project_id`; enabled metadata for another project does not satisfy this requirement. All matching OS Login settings must be enabled, so conflicting true and false settings fail. Unrelated updates to existing projects do not require metadata to be re-declared. The policy can only check resources declared in the plan. It cannot see OS Login settings managed outside this configuration, such as metadata in another Terraform workspace or the `compute.requireOsLogin` organization policy constraint. A new project that relies on one of those settings still fails, so declare the metadata in the same configuration or keep the policy at `advisory`. For existing projects outside this creation check, a passing instance-inheritance check does not prove that project-wide OS Login is enabled; that setting must be verified separately. Unresolved project identities or metadata values can yield an unknown result at plan time.

OS Login ties SSH access to IAM identities, so access is granted and revoked centrally and every login is attributable to a Google account. Metadata-managed SSH keys bypass IAM and are difficult to rotate or audit. An instance-level `enable-oslogin = FALSE` overrides the project setting, so instance overrides are enforced as well. The policy accepts only the values that the Compute Engine guest agent treats as true; `Y` and `Yes` are rejected because the guest agent does not enable OS Login for them. Values are matched exactly rather than case-insensitively. This intentionally differs from the `block-project-ssh-keys` (4.3) and `serial-port-enable` (4.5) policies, which accept the broader set of metadata boolean values. Instances that appear to be GKE nodes are not exempted.

This rule is covered by the [compute-os-login-enabled](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/compute/compute-os-login-enabled.policy.hcl) policy.
