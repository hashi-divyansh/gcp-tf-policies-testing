# Ensure That All BigQuery Tables Are Encrypted With Customer-Managed Encryption Key (CMEK)

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Encryption of data-at-rest |

## Description

This control checks that `google_bigquery_table` resources are encrypted with a customer-managed key. A table passes when it sets `encryption_configuration.kms_key_name`, or when a `google_bigquery_dataset` with the same `dataset_id` and project in the same plan sets `default_encryption_configuration.kms_key_name`. Tables in datasets that are not part of the plan must set their own key. Logical views, external tables, and BigLake tables are excluded because BigQuery does not store their data; materialized views are evaluated.

Customer-managed encryption keys (CMEK) let you control key rotation, access, and destruction in Cloud KMS, and disabling the key makes the data unreadable. Google-managed keys do not provide that control.

This rule is covered by the [7-2-bq-table-cmek](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/bigquery/7-2-bq-table-cmek.policy.hcl) policy.
