# Ensure 'Log_statement' Database Flag for Cloud SQL PostgreSQL Instance Is Set Appropriately

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Logging |

## Description

This control checks that Cloud SQL for PostgreSQL instances (`google_sql_database_instance` with a `POSTGRES` `database_version`) set the `log_statement` database flag to an approved value. The approved values come from the `log-statement-allowed-values` input, which defaults to `["ddl"]`. Values are compared case-insensitively. If the flag is not set, the effective value is `none`, which passes only when `none` is in the allowed list. Read replicas are evaluated too, because database flags are not inherited from the primary. The same check applies to `google_database_migration_service_connection_profile` resources that create a Cloud SQL destination instance through `cloudsql.settings.database_flags`.

`log_statement` controls which SQL statements PostgreSQL logs. Logging data definition (`ddl`) statements records schema changes for auditing without the volume of logging every statement. Organizations with different audit requirements can widen or change the allowed values with the input.

This rule is covered by the [6-2-4-log-statement](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/sql/6-2-4-log-statement.policy.hcl) policy.
