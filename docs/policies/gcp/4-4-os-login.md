# Ensure Oslogin Is Enabled for a Project

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Compute security |

## Description

This control checks that OS Login is enabled for Compute Engine. At the project level, a `google_compute_project_metadata` resource or a `google_compute_project_metadata_item` for `enable-oslogin` must set the value to a true value (`TRUE`, `true`, `True`, or `1`); an omitted or false value fails. At the instance level, `google_compute_instance`, `google_compute_instance_from_template`, `google_compute_instance_template`, and `google_compute_region_instance_template` may omit `enable-oslogin` to inherit the project setting, but if they set it, the value must be true.

OS Login ties SSH access to IAM identities, so access is granted and revoked centrally and every login is attributable to a Google account. Metadata-managed SSH keys bypass IAM and are difficult to rotate or audit. An instance-level `enable-oslogin = FALSE` overrides the project setting, so instance overrides are enforced as well. The policy accepts only the values that the Compute Engine guest agent treats as true; `Y` and `Yes` are rejected because the guest agent does not enable OS Login for them. Instances that appear to be GKE nodes are not exempted.

This rule is covered by the [4-4-os-login](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/compute/4-4-os-login.policy.hcl) policy.
