# Ensure That Cloud SQL Database Instances Do Not Have Public IPs

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Network security |

## Description

This control checks that primary Cloud SQL instances do not have a public IPv4 address. A `google_sql_database_instance` must set `settings.ip_configuration.ipv4_enabled` to `false` and connect privately, either through `private_network` (private services access) or with Private Service Connect (`psc_config.psc_enabled = true`). `ipv4_enabled` defaults to `true`, so omitting it fails. Read replicas and read pools are excluded through `instance_type` (or `master_instance_name` when `instance_type` is not set); set `instance_type` explicitly so that the result is known during a plan instead of reported as unknown.

Instances with a public IP address are reachable from the internet and depend on authorized networks and database authentication alone for protection. Private connectivity keeps database traffic inside your VPC network and lowers the risk of exposure.

This rule is covered by the [6-7-sql-no-public-ip](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/sql/6-7-sql-no-public-ip.policy.hcl) policy.
