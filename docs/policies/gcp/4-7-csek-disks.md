# Ensure VM Disks for Critical VMs Are Encrypted With Customer-Supplied Encryption Keys (CSEK)

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Compute security |

## Description

This control checks that Compute Engine disks are encrypted with customer-supplied encryption keys (CSEK). A `google_compute_disk` or `google_compute_region_disk` must set `disk_encryption_key.raw_key` or `disk_encryption_key.rsa_encrypted_key`, and every boot and attached disk of a `google_compute_instance` or `google_compute_instance_from_template` must supply a raw or RSA-wrapped key. Customer-managed keys (`kms_key_self_link`) do not satisfy this control. The optional `csek-disks-critical-label-key` input limits enforcement to resources that carry that label key in `labels` or `terraform_labels`; by default every disk is evaluated.

CSEK keeps the key material outside Google Cloud, so data on the disk cannot be read without the key you supply. **Note:** Google deprecated CSEK for Compute Engine. Since July 20, 2026, new Persistent Disks, images, and snapshots can no longer be encrypted with CSEK, and CSEK will be removed on July 20, 2027; Google recommends Cloud KMS customer-managed keys instead. Hyperdisk volumes do not support CSEK and therefore fail when in scope, and Local SSD scratch disks and instance templates are not evaluated because they cannot hold a CSEK.

This rule is covered by the [4-7-csek-disks](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/compute/4-7-csek-disks.policy.hcl) policy.
