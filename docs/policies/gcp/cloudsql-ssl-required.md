# Ensure That the Cloud SQL Database Instance Requires All Incoming Connections To Use SSL

| Provider | Category | CIS Control (GCP v5.0.0) |
| -------- | -------- | ------------------------ |
| Google Cloud Platform | Encryption of data-in-transit | 6.4 |

## Description

This control checks that `google_sql_database_instance` resources require encrypted connections. An explicit `settings.ip_configuration.ssl_mode` must be `ENCRYPTED_ONLY` or `TRUSTED_CLIENT_CERTIFICATE_REQUIRED` and takes precedence over the legacy `require_ssl` flag. On provider v6, an unset or empty `ssl_mode` is compliant when `require_ssl = true`. Provider v7 no longer exposes that legacy instance attribute, so it requires an explicit compliant `ssl_mode`. Omitting both settings is non-compliant.

The policy also checks `google_database_migration_service_connection_profile` resources that create a Cloud SQL destination through `cloudsql.settings`. These must set `cloudsql.settings.ip_config.require_ssl = true`, which is supported in both provider v6 and v7. Source-only profiles and references to existing Cloud SQL destinations without creation settings are outside this check.

Without enforced SSL/TLS, clients can connect over unencrypted channels, which exposes credentials and query results to interception and tampering. Requiring encrypted connections protects data in transit between applications and the database.

This rule is covered by the [cloudsql-ssl-required](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/sql/cloudsql-ssl-required.policy.hcl) policy.
