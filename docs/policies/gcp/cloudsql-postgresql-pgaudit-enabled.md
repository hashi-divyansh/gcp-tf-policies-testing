# Ensure That 'cloudsql.enable_pgaudit' Database Flag for each Cloud Sql Postgresql Instance Is Set to 'on' For Centralized Logging

| Provider | Category | CIS Control (GCP v5.0.0) |
| -------- | -------- | ------------------------ |
| Google Cloud Platform | Logging | 6.2.8 |

## Description

This control checks that Cloud SQL for PostgreSQL instances (`google_sql_database_instance` with a `POSTGRES` `database_version`) set the `cloudsql.enable_pgaudit` database flag to `on`. Values are compared case-insensitively. If the flag is not set, the instance fails because the engine default is non-compliant. Read replicas are evaluated too, because database flags are not inherited from the primary. The same check applies to `google_database_migration_service_connection_profile` resources that create a Cloud SQL destination instance through `cloudsql.settings.database_flags`.

The pgAudit extension provides detailed session and object audit logging through Cloud Logging. The flag only makes the extension available. [Google's setup instructions](https://cloud.google.com/sql/docs/postgres/pg-audit) also require running `CREATE EXTENSION pgaudit` in each database, configuring `pgaudit.log`, and enabling Data Access audit logs to view the generated logs. These steps are outside this flag-only policy's scope. Data Access audit logging can be configured in Terraform through `google_project_iam_audit_config`; runtime database-extension state is not exposed by these Google provider resources.

This rule is covered by the [cloudsql-postgresql-pgaudit-enabled](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/sql/cloudsql-postgresql-pgaudit-enabled.policy.hcl) policy.
