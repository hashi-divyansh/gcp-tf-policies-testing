# Ensure 'Log_min_error_statement' Database Flag for Cloud SQL PostgreSQL Instance Is Set to 'Error' or Stricter

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Logging |

## Description

This control checks that Cloud SQL for PostgreSQL instances (`google_sql_database_instance` with a `POSTGRES` `database_version`) set the `log_min_error_statement` database flag to `error` or a more severe level (`log`, `fatal`, or `panic`), if it is set. Values are compared case-insensitively. If the flag is not set, the instance passes because the engine default is compliant. Read replicas are evaluated too, because database flags are not inherited from the primary. The same check applies to `google_database_migration_service_connection_profile` resources that create a Cloud SQL destination instance through `cloudsql.settings.database_flags`.

`log_min_error_statement` controls which failing SQL statements are written to the log together with the error. Logging statements that cause errors helps identify attacks such as SQL injection probing, while lower levels add noise.

This rule is covered by the [6-2-6-log-min-error-statement](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/sql/6-2-6-log-min-error-statement.policy.hcl) policy.
