# Ensure that the 'Log_min_messages' Flag for a Cloud SQL PostgreSQL Instance is set at minimum to 'Warning'

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Logging |

## Description

This control checks that Cloud SQL for PostgreSQL instances (`google_sql_database_instance` with a `POSTGRES` `database_version`) set the `log_min_messages` database flag to `warning` or a more severe level (`error`, `log`, `fatal`, or `panic`), if it is set. Values are compared case-insensitively. If the flag is not set, the instance passes because the engine default is compliant. Read replicas are evaluated too, because database flags are not inherited from the primary. The same check applies to `google_database_migration_service_connection_profile` resources that create a Cloud SQL destination instance through `cloudsql.settings.database_flags`.

`log_min_messages` sets the lowest severity that PostgreSQL writes to the server log. Levels below `warning` (`notice`, `info`, and `debug*`) generate large volumes of noise, while overly restrictive settings can hide warnings that are relevant to troubleshooting and security monitoring.

This rule is covered by the [6-2-5-log-min-messages](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/sql/6-2-5-log-min-messages.policy.hcl) policy.
